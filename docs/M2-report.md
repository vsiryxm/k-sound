## 1. 交付物

| 文件 | 说明 |
|---|---|
| `app.py` | FastAPI 后端：任务式接口 + 单工作线程 + 三步链路子进程复刻 |
| `static/index.html` | 前端单页（原生 HTML/JS，无框架，深色 OLED 风格） |

| `engine/infer_svc.py` | 仅追加 `[chunk] N/M` 进度打印，推理逻辑零改动 |
| `jobs/<id>/` | 任务数据（上传件、中间产物、成品、status.json 状态持久化） |

接口：

- `POST /jobs` — 上传 `voice` + `song` + `authorized=true`，同步校验（格式/解码/时长/音量），返回 `job_id`
- `GET /jobs/{id}` — 状态（queued/running/done/error）、阶段（preprocess/demucs/svc/remix）、块级进度 detail、错误信息
- `GET /jobs/{id}/result?fmt=mp3|wav` — 成品下载（`_AI` 后缀）
- `GET /` — 前端页面

## 3. 本次新增的第五个坑：HF_HOME 指错缓存（已修复）

- **现象**：Web 服务子进程加载 whisper-small 报 `couldn't find it in the cached files`，M1 命令行同参数却正常。
- **根因**：Agent 运行环境自带 `HF_HOME=/Users/xinmin/.cache/TeleAgent/huggingface`（另一份空缓存），uvicorn 子进程继承后在**错误目录**找模型；真实缓存在 `~/.cache/huggingface`。且该机器出网必须走代理（127.0.0.1:7890），M1 之所以成功是用户 shell 里有代理变量，代理通了 HEAD 校验。
- **修复**（`app.py` 的 `_child_env`）：子进程环境显式 `HF_HOME=~/.cache/huggingface` + `HF_HUB_OFFLINE=1` 纯离线解析（所有模型 refs/main 完好），并剔除代理变量。效果：**运行期零联网、零代理依赖**，模型加载 4.1s，比 M1 联网校验模式更快。
- 注意：Seed-VC checkpoint / rmvpe 走项目内 `./checkpoints`（cwd 相对），子进程 cwd 固定为项目根即可命中，两路缓存互不影响。

## 5. 生成统计（M2+ 增量：成本估算用）

生成完成后，成品区显示统计卡片与分阶段明细，同时写入 `GET /jobs/{id}` 的 `stats` 字段：

| 字段 | 含义 | 实测值（贝加尔湖畔 284s） |
|---|---|---|
| `total_s` | 总耗时（worker 接起到完成） | 223.2s |
| `stage_times` | 分阶段墙钟：preprocess / demucs / svc / remix | 0.2 / 7.7 / 213.1 / 2.1s |
| `speed_x` | 生成速度 = 成品时长 ÷ 总耗时 | 1.27× 实时 |
| `model_load_s` | SEED-VC 模型加载耗时（含于 svc 阶段） | 2.3s（离线缓存生效，M1 联网模式 8s） |
| `peak_rss_gb` | 转换进程峰值 RSS（infer_svc `[perf]` 解析） | 2.43 GB |
| `demucs_peak_rss_gb` | 分离进程峰值 RSS（`engine/run_with_peak.py` 包装器测量） | 2.68 GB |
| `mps_current_gb` / `mps_driver_gb` | 结束时 MPS 当前/驱动分配显存 | 1.84 / 5.31 GB |
| `svc_rtf` | 扩散+BigVGAN 阶段 RTF（infer_svc 自报） | 0.662 |

实现要点：
- Demucs 峰值内存经 `engine/run_with_peak.py` 包装测量（`getrusage(RUSAGE_CHILDREN)`，天然隔离于服务进程的其他子进程）。
- 顺带把 `_run` 的子进程改为独立进程组（`start_new_session`），超时按组 SIGKILL，包装器与孙进程不会变孤儿。
- 旧任务（无 stats 字段）前端自动隐藏统计区，向后兼容。

## 8. M2+ 第三轮增量（批次聚合历史）

- **批次号**：一次生成操作 = 一个批次，`batch_id` = `job_id`（API 显式下发：`POST /jobs` 响应与 `GET /jobs/{id}` 均含 `batch_id` 字段）；一个批次天然集合「干声 / 源歌 / 翻唱」三件套
- **历史按批次聚合**：`GET /history` 返回批次卡片化数据；前端每批次一张卡片，卡内直接集成「翻唱 / 原唱 / 我的干声」三音源切换 + 播放器 + MP3/WAV 下载 + 统计（速度/内存/耗时），同屏对比一次生成处理的三个效果
- **分页**：`GET /history?offset=&limit=`（默认每页 10 批次，返回 `total / has_more`）；前端「加载更多批次」按钮追加加载，≤10 个批次时分页栏自动隐藏
- 批次卡片内切音源保持播放进度；成品文件已清理的批次整卡置灰并禁播禁下载
- 修复：批次卡 `audio` 改 `preload="metadata"`（初始无 src 零流量；否则切源后 metadata 不加载导致进度不恢复）

## 9. M2+ 第四轮增量（人声混响 · 响应用户朋友听感反馈）

**需求背景**：试听反馈「AI 人声偏干、缺混响」。根因：SEED-VC 输出为干净歌声分布，且回混是裸叠加——干声 vs 带录音室空间的伴奏不在同一声场。质量档（扩散步数）管"画质"不管"空间感"，调精细档不能解决。

- **方案 A 落地**：`pedalboard`（Spotify 开源，0.9.26，本机运行）`Reverb(room_size=0.35, damping=0.6)` 只加在人声轨，再与伴奏混合——把 AI 人声"推回"伴奏声场
- **湿度可调**：设置项 `reverb_wet`（0–30%，默认 18%），设置弹窗新增滑条（干声/极轻/自然/较浓 档位描述），即时生效于下次生成；结果卡与历史批次 badge 显示「混响N%」
- 客观验证：人声停顿处余响能量为干声的 ~4300 倍（0.066 vs 0.00002），峰值 0.95 无削波；fast 档混响版端到端 2 分 54 秒（1.63× 实时），混响处理本身耗时 <1 秒
- DB：jobs 表加 `reverb_wet` 列（含旧库幂等迁移）；已有批次湿度过旧代码入库为 0，仅展示问题、不影响新任务
- 依赖新增：`pedalboard`（uv 安装入 .venv，纯本地音频 DSP，无联网）

## 11. M2+ 第五轮增量（干声上传放宽至 5 分钟 · 自动截断）

- 上传上限 90s → **300s（5 分钟）**；后端预处理自动截取**前 15 秒**做音色参考（完整干声保留在 upload/ 供「我的干声」试听）
- **关键发现（本轮踩坑）**：SEED-VC 的参考干声会占用转换上下文窗口（30s − 参考时长 = 每块可用窗口）——参考 30s 时窗口归零、分块暴涨 18→58 块、耗时×3；故截断值定 15s（音色稳定与速度平衡，官方建议 5–10s，13.4s 实测四维初评通过）
- 实测：2 分钟干声上传 → 15s 截断 → 19 块（正常水平）→ 成品电平 -0.7dB 峰值无削波，试听源完整
- 文案诚实化：明确「系统自动截取前 15 秒」，避免此前「30 秒上限」的误导表述
- **顺带修复严重 bug**：`_db_upsert_job` 加 `reverb_wet` 列后占位符少写一个 `?`（24 列 23 值）导致入库静默失败——混响轮起所有批次未入库；已修复并把缺失批次全部回补。教训：静默吞异常的兜底掩盖了列数不匹配，已用真实数据复现验证
