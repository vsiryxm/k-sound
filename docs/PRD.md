# k-sound 产品需求文档（PRD · MVP）

> 本地 AI 音色翻唱工具 · 决策已确认 · 技术可行性待 M1 验证 · 供新会话开发 DEMO 使用

## 1. 一句话定位

在本机跑一个网页工具：上传一段「我的音色」、指定一首歌，一键生成「用我的音色唱这首歌」的成品音频，在线试听并下载。

**说明**：本 PRD 的引擎选型为「待验证方案」，非已证明结论——M1 阶段跑通后，再确认是否沿用。

## 2. 目标用户与场景

- **MVP 用户**：你自己（先验证音色翻唱效果是否可用）。
- **核心场景**：不想学模型、不想敲命令，浏览器里点几下就出翻唱成品。

## 3. 核心目标 vs 非目标

### 本期要做（核心功能）
1. 上传音色参考音频
2. 指定目标歌曲
3. 一键生成翻唱
4. 在线试听 + 下载成品

### 本期不做
- 训练专属声模、实时变声（本期用 zero-shot 免训练方案）
- 歌名搜索、曲库、多音色管理、登录注册（接口预留扩展，但不实现）
- 波形图预览、语音水印、多音色混合/合唱
- 移动端、商业化付费、云端部署
- Intel Mac / Windows 跨平台（目标硬件固定为 Apple Silicon 本机）

## 4. 用户操作流程（核心交互）

```
打开页面
  → ① 拖入/选择「我的音色」样本（自动音量标准化 + 质量提示）
  → ② 拖入/选择「目标歌曲」音频
  → ③ 勾选本人授权
  → ④ 点「生成翻唱」
  → ⑤ 看分步进度（分离人声 → 音色转换 → 混音导出）
  → ⑥ 在线试听（手动播放）
  → ⑦ 下载成品
```

## 5. 功能需求（MVP）

| 编号 | 功能 | 说明 | 优先级 |
|---|---|---|---|
| F1 | 音色上传 | 拖拽/点击上传本人清晰人声 10–30 秒（单人、清唱或朗读、无伴奏/无混响/无明显噪声），自动音量标准化；超低音量/全静音给出提示 | P0 |
| F2 | 歌曲指定 | 上传目标歌曲音频文件（mp3/wav/m4a） | P0 |
| F3 | 翻唱生成 | 后端调用 SEED-VC 做歌声转换（zero-shot，免训练） | P0 |
| F4 | 进度反馈 | 分步进度条（分离人声 → 转换 → 混音）+ 错误提示 | P0 |
| F5 | 试听 + 下载 | 手动点击播放 + 下载 + 重新生成 | P0 |
| F6 | 授权确认 | 首次弹授权说明，手动勾选；本地仅记录「已同意」状态，不收集数据 | P0（合规） |

### 参考音频质量要求（F1）
- 单人、单声部；无背景音乐、无混响、无和声、无明显压缩失真
- 音色样本建议包含不同音高与多个元音；说话样本可用，但清唱样本对歌唱转换更稳
- **检测范围（MVP）**：仅自动检测「无法解码、全静音、超低音量」；其余（无伴奏、无混响、无和声等）通过界面文案提示，**不做自动识别**

### 支持范围声明
- MVP 支持**主流录音室流行歌曲（单人主唱）**
- 现场录音、合唱/双人合唱、强混响、纯音乐等**不在支持范围**

### 常见错误提示（至少覆盖）
- 音频格式不支持 / 解码失败
- 音色样本过短或全静音
- 歌曲人声分离失败（无人声 / 非单人主唱 / 质量过低）
- 生成超时或内存不足

## 6. 界面与交互设计（便捷操作）

单页、三段式布局，界面风格**简洁、大气、优雅**，零学习成本：

```
┌─────────────────────────────────────────────┐
│  k-sound · 用我的声音唱歌                      │
│                                              │
│  ┌─────────────────┐  ┌─────────────────┐   │
│  │ ① 我的音色        │  │ ② 目标歌曲       │   │
│  │  [拖拽或点击上传]  │  │  [拖拽或点击上传] │   │
│  │  10–30秒清晰干声  │  │  mp3/wav/m4a    │   │
│  └─────────────────┘  └─────────────────┘   │
│                                              │
│  ☑ 音色为本人所有，仅本地使用                   │
│                                              │
│            [ 生成翻唱 ]  ← 大按钮             │
│    ① 分离人声  →  ② 音色转换  →  ③ 混音导出   │
│    （当前步高亮）                              │
│                                              │
│  ┌─────────────────────────────────────┐    │
│  │ ③ 成品   ▶ 点击播放   [下载]  [重新生成] │   │
│  └─────────────────────────────────────┘    │
└─────────────────────────────────────────────┘
```

交互原则：
- 拖拽即用、点选即用，两种上传方式都支持
- 按钮状态：**两个文件都上传 + 授权勾选后按钮才可点击**，否则置灰并提示缺哪项
- 生成中：分步进度条，当前步骤高亮；不估算剩余时间（本机推理波动大，估算会误导）
- 生成后：手动点击播放，不自动出声
- 出错：明确到具体原因（见上表）

## 7. 技术方案（含关键实现约束）

- **后端**：Python FastAPI，**任务式接口**（长任务不能靠同步请求扛）：
  - `POST /jobs`：上传 `voice`（音色）+ `song`（歌曲），创建任务，返回 `job_id`
  - `GET /jobs/{id}`：查询当前阶段、状态、错误信息
  - `GET /jobs/{id}/result`：下载成品音频
- **引擎**：SEED-VC（zero-shot 歌声转换，Apple Silicon MPS 原生支持，唱歌解码用 BigVGAN）
  - **M1 待办**：确定并使用 singing checkpoint（f0-condition 歌声模型，44.1kHz）与 F0 提取配置，避免误用普通语音 VC 配置（22.05kHz）导致音高/歌唱表现失败
- **分轨**：Demucs（htdemucs）分离歌曲人声（再喂给 SEED-VC 换音色）
- **前端**：单页 HTML + 原生 JS，无框架，轮询 `GET /jobs/{id}` 更新进度；界面设计用 **ui-ux-pro-max skill** 指导，风格简洁、大气、优雅
- **运行**：本机 localhost；**首次运行需联网下载模型权重（HuggingFace），运行期数据不出网**

### 关键实现约束（新会话开发必读）
- **Python 版本**：用 **3.10 或 3.11**（SEED-VC 官方建议 3.10；本机默认 `python3` 是 3.14，PyTorch/SEED-VC 不兼容，必须新建独立 venv/conda 环境）
- **核心依赖**：`torch`（Apple Silicon MPS 版）、`seed-vc`、`fastapi`、`uvicorn`、`demucs`（人声分离）、`ffmpeg`（系统依赖）
- **目标硬件**：M5 Max，18 核，64GB 内存，macOS（Apple Silicon MPS）

## 8. 验收标准

### 8.1 功能验收标准（按 P0 功能逐条可测试）

| 功能 | 验收标准（满足即为完成） |
|---|---|
| F1 音色上传 | 支持拖拽/点击上传 wav/mp3/m4a；上传后显示文件名与时长；超低音量/全静音给出明确提示 |
| F2 歌曲指定 | 支持拖拽/点击上传 mp3/wav/m4a；格式不支持时给出明确错误提示 |
| F3 翻唱生成 | 提交任务后，后端成功返回一段「用上传音色演唱」的成品音频 |
| F4 进度反馈 | 生成过程展示「分离人声 → 音色转换 → 混音导出」分步进度；出错时显示具体原因 |
| F5 试听 + 下载 | 成品可手动点击播放试听；可一键下载；可重新生成 |
| F6 授权确认 | 首次进入弹授权说明；勾选后生成按钮才可用；再次进入不重复弹（本地已记录同意） |

### 8.2 质量验收标准（按维度拆分，用户本人主观评估）

| 维度 | 标准 |
|---|---|
| 音色相似度 | 5 分制 ≥ 3.5（1=完全不像，5=几乎一致） |
| 歌词可懂度 | 无明显吞字、错字、含糊 |
| 音高与节奏 | 无明显跑调、节奏错乱 |
| 音频伪影 | 无严重机械噪声、无「双人声」残留（原人声泄漏） |

### 8.3 性能验收标准（初始目标，M1 实测后校准）

- M5 Max 上，单首 3–5 分钟歌曲全流程（分轨+转换+混音）目标 ≤ 5 分钟（**未经实测，M1 记录后校准**）
- 音质：采样率 44.1kHz，导出 mp3 320kbps 或 wav 无损
- 容错：覆盖 ≥3 种常见错误的友好提示

### 8.4 端到端验收标准

- 全流程纯浏览器操作，无任何命令行
- 上传本人音色 + 一首歌 → 得到可下载成品，能明显听出是上传音色在演唱

## 9. 风险与合规

- 仅限本人音色：首次使用弹授权说明，手动勾选，本地仅记录「已同意」状态（不收集数据）
- 成品标注：文件名自动追加 `_AI` 后缀（**MVP 轻量标识，非完整合规方案**）
- 本地运行仅**降低数据外传风险，不能完全规避合规风险**；本人音色授权 ≠ 歌曲词曲/录音/伴奏版权，商用前需另行取得授权

## 10. 里程碑（开发顺序）

- **M1**：后端模型跑通——SEED-VC singing checkpoint 单次转换成功，生成**可试听的完整结果**，并由本人按 8.2 四维度做一次**初评**（音色相似度、歌唱可用性）；不达标则记录失败原因、**不判定 M1 成功**。同时记录：3 分钟歌曲各阶段耗时、峰值内存、是否发生 MPS fallback、是否出现分块接缝
- **M2**：前端与后端联调（上传 → 任务创建 → 进度轮询 → 下载全链路）
- **M3**：用真实音色端到端验证效果，按 8.2 四维度正式打分。**失败判定**：若音色相似度 < 3.5，或出现明显跑调、双人声、严重伪影，判定当前方案验证失败，进入「参数调整 → 分轨替换 → 模型替换」的评估；不得仅以「文件可下载」作为完成

---

## 已确认的决策

1. **引擎方向**：SEED-VC zero-shot 免训练（决策已锁定；具体 checkpoint / F0 配置在 M1 阶段确定并验证）
2. **「指定歌曲」方式**：MVP 只做「上传歌曲音频文件」，不做歌名搜索
3. **界面形式**：单页原生 HTML（最简、最快）；界面风格简洁、大气、优雅，用 ui-ux-pro-max skill 指导设计
4. **接口形式**：任务式（POST /jobs → GET /jobs/{id} → GET /jobs/{id}/result）
5. **后续迭代方向（本期不做）**：训练专属声模、歌名搜索、波形图预览、语音水印
